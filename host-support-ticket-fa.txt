# تیکت پشتیبانی — دو موضوع: دسترسی SSH و گواهی SSL سرویس FTP

**کاربر:** `cognikat`
**دامنه:** `cognika.tech`
**سرور:** `best.hyperhosty.com` / `5.9.176.204`
**تاریخ:** ۲۸ اکتبر ۲۰۲۶
**اولویت:** متوسط

---

## خلاصه

دو مشکل جداگانه داریم که هر دو مربوط به دسترسی و انتقال فایل است:

۱. **دسترسی SSH برای کاربر `cognikat` فعال نیست** و پورت آن مشخص نیست.
۲. **گواهی SSL سرویس FTPS با نام `ftp.cognika.tech` مطابقت ندارد** و اتصال امن را ناموفق می‌کند.

لطفاً موارد زیر را بررسی و راهنمایی بفرمایید.

---

## موضوع ۱ — فعال‌سازی دسترسی SSH و اعلام شماره پورت

### وضعیت فعلی

کلید عمومی ما در سرور نصب و تأیید شده است. خروجی دستور زیر روی سرور:

```bash
ssh-keygen -lf ~/.ssh/authorized_keys
```

نتیجه:

```
2048 SHA256:13rb9578i+ki2pqYfnqESOOQG16932/66iuFoSjHgzE no comment (RSA)
2048 SHA256:7lhF4w/H9QvzIFiJPIbAG1pZI807hBVNJ0YH87pKKTc cognika-mac (RSA)
```

خط دوم کلید ما (`cognika-mac`) است که با موفقیت اضافه شده است.

### مشکل

اتصال SSH به دامنه از سمت ما برقرار نمی‌شود و پورت ۲۲ بسته است. روی این پورت‌ها هم تست شد و همه بسته بودند:

```
22, 2222, 2200, 2022, 222, 8022, 9922
```

خروجی اتصال:

```
ssh: connect to host cognika.tech port 22: Connection refused
```

با توجه به اینکه روی این سرور کنترل‌پنل cPanel و CloudLinux (CageFS) نصب است و کاربر `cognikat` دسترسی `sudo` ندارد، احتمال می‌دهیم:

- دسترسی SSH برای این اکانت از سمت کنترل‌پنل **غیرفعال** است، یا
- سرویس SSH روی **پورت غیر‌استاندارد** اجرا می‌شود.

### درخواست

۱. لطفاً دسترسی SSH را برای کاربر `cognikat` و دامنه `cognika.tech` **فعال** بفرمایید.
۲. **شماره پورت SSH** را اعلام کنید تا بتوانیم متصل شویم.
۳. اگر محدودیت IP وجود دارد، لطفاً اعلام کنید تا IP ما را در اختیارتان قرار دهیم.
۴. اگر کلید RSA از نوع `ssh-rsa` (با الگوریتم SHA-1) به‌صورت پیش‌فرض غیرفعال است، لطفاً مقدار زیر را در `sshd_config` سرور تنظیم بفرمایید:

```
PubkeyAcceptedAlgorithms +ssh-rsa
```

> **توضیح:** کلید ما RSA 2048 است. در نسخه‌های جدید OpenSSH (نسخه ۸.۸ به بالا) الگوریتم `ssh-rsa` به‌صورت پیش‌فرض غیرفعال شده و اتصال با خطای `Permission denied (publickey)` رد می‌شود. اگر ترجیح می‌دهید از کلید جدید استفاده کنیم، ما می‌توانیم کلید `ed25519` بسازیم و خدمتتان ارسال کنیم.

## موضوع ۲ — عدم تطابق گواهی SSL در سرویس FTPS

### وضعیت فعلی

سرویس FTP روی پورت ۲۱ فعال است و پاسخ می‌دهد:

```
220---------- Welcome to Pure-FTPd [privsep] [TLS] ----------
220-You are user number 1 of 50 allowed.
220-This is a private system - No anonymous login
```

پشتیبانی از TLS هم اعلام می‌شود:

```
AUTH TLS → 234 AUTH TLS OK
```

### مشکل

هنگام اتصال امن (FTPS) به `ftp.cognika.tech`، گواهی ارائه‌شده با نام میزبان مطابقت ندارد.

بررسی گواهی:

```bash
echo | openssl s_client -connect ftp.cognika.tech:21 -starttls ftp \
  -servername ftp.cognika.tech 2>/dev/null | openssl x509 -noout -subject -issuer
```

نتیجه:

```
subject=CN=best.hyperhosty.com
issuer=C=US, O=Let's Encrypt, CN=YR1
```

خطای کلاینت:

```
curl: (60) SSL: no alternative certificate subject name matches
target host name 'ftp.cognika.tech'
```

همین خطا برای نام `cognika.tech` هم رخ می‌دهد، چون گواهی صرفاً برای `best.hyperhosty.com` صادر شده است.

### درخواست

۱. لطفاً گواهی SSL سرویس FTP را به‌گونه‌ای تنظیم بفرمایید که نام‌های `cognika.tech` و `ftp.cognika.tech` در فیلد **SAN (Subject Alternative Name)** گواهی قرار گیرند.

   در cPanel مسیر: **SSL/TLS Status → cognika.tech → Run AutoSSL** (یا نصب گواهی Let's Encrypt با نام‌های اضافی).

۲. در صورت امکان، تأیید بفرمایید که سرویس FTP **Explicit FTPS** را به‌صورت کامل پشتیبانی می‌کند.

> **توضیح:** بدون این اصلاح، ابزارهای خودکار استقرار (مانند GitHub Actions با تنظیم `security: strict`) نمی‌توانند از FTPS استفاده کنند و مجبور به غیرفعال‌کردن بررسی گواهی می‌شویم که از نظر امنیتی توصیه نمی‌شود.

## موضوع مرتبط (اختیاری) — ورود FTP با خطای 530

در جریان تست‌ها، ورود به FTP با کاربر `cognikaftp@cognika.tech` با خطای زیر رد می‌شد:

```
331 User cognikaftp OK. Password required
530 Login authentication failed
```

این خطا با دو رمز عبور مختلف (که پس از تغییر رمز در کنترل‌پنل تنظیم شده بودند) و هم روی TLS و هم روی FTP ساده تکرار شد. کاربر توسط سرور شناسایی می‌شود (`331`) اما احراز هویت رد می‌شود (`530`).

لطفاً بررسی بفرمایید که آیا:

- اکانت FTP در سمت سرور **قفل** شده است (احتمالاً به دلیل تلاش‌های ناموفق متوالی)،
- و یا سرویس احراز هویت FTP (`plesk`/Pure-FTPd backend) نیاز به بازنشانی دارد.

اگر نیاز به بازنشانی رمز از سمت شماست، لطفاً اعلام بفرمایید.
